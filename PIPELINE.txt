# Pipeline nghiên cứu của dự án

Tài liệu này mô tả pipeline nghiên cứu của dự án theo góc nhìn dữ liệu, tiền xử lý, feature engineering, mô hình, đầu ra và đánh giá. Đây không phải là hướng dẫn chạy code từng lệnh, mà là bản giải thích logic hoạt động của toàn bộ pipeline để nhóm có thể đọc và thống nhất cách hiểu.

## 1. Mục tiêu nghiên cứu

Dự án nghiên cứu việc phát hiện và phân biệt nhiễu trong các hệ tín hiệu bằng các đặc trưng complexity.

Câu hỏi chính:

1. Các complexity metrics có giúp nhận diện tín hiệu sạch và tín hiệu có nhiễu không?
2. Các complexity metrics có giúp phân biệt loại nhiễu không?
3. Các complexity metrics có giúp phân biệt mức độ nhiễu không?
4. Kết quả có khác nhau giữa các hệ tín hiệu như ECG, Lorenz, Rössler, Hénon và AR(1) không?

Pipeline không dự báo giá trị tiếp theo của chuỗi thời gian. Pipeline biến mỗi cửa sổ tín hiệu thành một vector đặc trưng complexity, sau đó dùng mô hình phân loại để dự đoán trạng thái nhiễu.

Tổng quan:

```text
Tín hiệu sạch
-> chuẩn hóa z-score
-> thêm nhiễu có kiểm soát
-> cắt rolling window
-> trích xuất 18 complexity metrics
-> tạo bảng dữ liệu ML
-> CatBoost phân loại
-> đánh giá bằng group-aware splits
-> phân tích confusion matrix, feature importance, SHAP/permutation
```

## 2. Dữ liệu đầu vào

Dữ liệu trong dự án là dữ liệu synthetic/controlled, được tạo từ 5 hệ:

| Hệ tín hiệu | Mô tả |
| --- | --- |
| ECG | Tín hiệu ECG mô phỏng bằng NeuroKit2 |
| Lorenz | Hệ chaotic liên tục, lấy thành phần x(t) |
| Rössler | Hệ chaotic liên tục, lấy thành phần x(t) |
| Hénon | Bản đồ chaotic rời rạc, lấy chuỗi x[n] |
| AR(1) | Baseline autoregressive AR(1) |

Mỗi hệ tạo nhiều lần lặp `run_id`. Mặc định trong các script hiện tại:

```text
n_runs = 20
```

Với mỗi `run_id`, pipeline tạo một tín hiệu sạch. Từ cùng tín hiệu sạch đó, pipeline tạo các bản bị nhiễu với các loại và mức nhiễu khác nhau. Như vậy, các bản clean/noisy trong cùng `run_id` có cùng nền tín hiệu gốc, chỉ khác trạng thái nhiễu.

## 3. Cấu hình nhiễu

Các loại nhiễu và mức nhiễu:

| Loại nhiễu | Mức cường độ |
| --- | --- |
| Gaussian | 1, 0.3, 0.1 |
| Pink | 2, 1, 0.2 |
| Low-frequency | 0.2, 1, 2 |
| Clean | none, intensity = 0 |

Với mặc định 20 run:

```text
Mỗi run có:
- 1 tín hiệu clean
- 9 tín hiệu noisy = 3 loại nhiễu x 3 mức cường độ

Tổng mỗi hệ:
20 x (1 + 9) = 200 tín hiệu
```

## 4. Tiền xử lý tín hiệu

Mỗi tín hiệu sạch được chuẩn hóa z-score trước khi thêm nhiễu:

```text
x_norm = (x - mean(x)) / std(x)
```

Sau đó nhiễu được cộng trực tiếp lên tín hiệu đã chuẩn hóa.

### Gaussian noise

```text
x_noisy = x_norm + N(0, intensity)
```

### Pink noise

Pink noise được tạo theo miền tần số với dạng gần 1/f. Sau khi tạo, pink noise được chuẩn hóa về trung bình 0, độ lệch chuẩn 1, rồi nhân với `intensity`:

```text
x_noisy = x_norm + intensity * pink_noise
```

### Low-frequency noise

Low-frequency noise là thành phần sin tần số thấp:

```text
x_noisy = x_norm + intensity * sin(2*pi*f*t + phase)
```

Trong code, `f` được random trong khoảng xấp xỉ `0.45 - 0.55`, và `phase` cũng được random.

## 5. Metadata và định danh

Mỗi tín hiệu được lưu kèm metadata:

```text
split
noise_type
noise_intensity
run_id
signal_id
npz_path
```

Quy ước quan trọng:

```text
signal_id = str(run_id)
```

Trong các bước ML, `signal_id` là định danh duy nhất được dùng để chia train/test theo run. Điều này giúp tránh rò rỉ dữ liệu giữa train và test.

## 6. Tạo mẫu ML bằng rolling window

Sau khi có tín hiệu clean/noisy, pipeline cắt mỗi tín hiệu thành nhiều cửa sổ trượt.

Cấu hình hiện tại:

```text
memory_complexity = 300
window_step = 100
```

Mỗi cửa sổ dài 300 sample. Cửa sổ tiếp theo dịch đi 100 sample.

Ví dụ:

```text
signal[0:300]     -> sample ML 1
signal[100:400]   -> sample ML 2
signal[200:500]   -> sample ML 3
...
```

Mỗi cửa sổ trở thành một dòng trong bảng dữ liệu ML.

Đơn vị học của mô hình:

```text
1 dòng ML = 1 rolling window của 1 tín hiệu
```

## 7. Feature engineering

Với mỗi rolling window, pipeline tính 18 đặc trưng complexity/statistical/SVD.

Danh sách features:

| Feature | Nhóm ý nghĩa |
| --- | --- |
| `var1der` | Biến thiên đạo hàm bậc 1 trên embedding |
| `var2der` | Biến thiên đạo hàm bậc 2 trên embedding |
| `std_dev` | Độ lệch chuẩn của window |
| `mad` | Mean absolute deviation |
| `cv` | Coefficient of variation |
| `approximate_entropy` | Entropy gần đúng |
| `sample_entropy` | Sample entropy |
| `permutation_entropy` | Permutation entropy |
| `lempel_ziv_complexity` | Độ phức tạp Lempel-Ziv |
| `dfa` | Detrended fluctuation analysis |
| `hurst` | Hurst exponent |
| `fisher_info` | Fisher information từ sai phân |
| `fisher_info_nk` | Fisher information theo NeuroKit2 |
| `svd_entropy` | Entropy từ SVD |
| `rel_decay` | Tốc độ suy giảm tương đối của singular values |
| `svd_energy` | Năng lượng trong các singular values đầu |
| `condition_number` | Condition number của embedding matrix |
| `spectral_skewness` | Skewness của phổ singular values |

Pipeline dùng hai cấu hình delay embedding:

```text
DYN embedding:
  dimension = 3
  delay = 1

SVD embedding:
  dimension = 10
  delay = 1
```

Một số feature tính trực tiếp trên raw window. Một số feature tính trên delay embedding. Một số feature tính từ singular values của embedding matrix.

Kết quả của bước này là bảng ML:

```text
X = 18 complexity metrics
y = label tùy theo task
metadata = noise_type, noise_intensity, signal_id, window index
```

## 8. Các bài toán phân loại

Pipeline tạo 3 task phân loại.

### Task 1: Phân loại loại nhiễu

Label:

```text
noise_label_task1
```

Classes:

```text
none
gaussian
pink
low_freq
```

Mục tiêu: mô hình dự đoán tín hiệu thuộc loại sạch hay bị loại nhiễu nào.

### Task 2: Phân loại loại nhiễu và cường độ

Label:

```text
noise_label_task2
```

Classes:

```text
none_0
gaussian_1.0
gaussian_0.3
gaussian_0.1
pink_2.0
pink_1.0
pink_0.2
low_freq_0.2
low_freq_1.0
low_freq_2.0
```

Mục tiêu: mô hình không chỉ nhận diện loại nhiễu, mà còn nhận diện mức cường độ nhiễu.

### Task 3: Phát hiện có nhiễu hay không

Label:

```text
noise_present
```

Classes:

```text
0 = clean
1 = noisy
```

Mục tiêu: bài toán binary classification, chỉ cần biết tín hiệu có bị nhiễu hay không.

## 9. Mô hình

Mô hình chính:

```text
CatBoostClassifier
```

Input của mô hình:

```text
18 complexity features
```

Output của mô hình:

```text
Class label của Task 1, Task 2 hoặc Task 3
```

Pipeline hiện tại chủ yếu dùng CatBoost out-of-the-box, không tập trung vào tuning hyperparameter. Trong mỗi split, model được train lại từ đầu với seed riêng.

## 10. Chia train/test và chống leakage

Đây là điểm quan trọng của pipeline.

Vì mỗi tín hiệu dài được cắt thành nhiều rolling window, các window trong cùng một `run_id` rất liên quan với nhau. Nếu chia train/test ngẫu nhiên theo từng dòng, một số window của cùng một tín hiệu có thể nằm trong train và test cùng lúc. Khi đó, kết quả đánh giá sẽ bị optimistic vì model đã thấy các mẫu rất gần với test trong train.

Để tránh vấn đề này, pipeline chia train/test theo `signal_id`, tức theo `run_id`.

Nguyên tắc:

```text
Tất cả window của cùng một signal_id chỉ nằm trong train hoặc chỉ nằm trong test.
Không có signal_id nào xuất hiện đồng thời ở train và test.
```

Cấu hình hiện tại:

```text
N_SPLITS = 50
TEST_SIZE = 0.20
BASE_RANDOM_SEED = 42
```

Với 20 run, mỗi split thường lấy khoảng 20% run làm test, phần còn lại làm train.

Pipeline còn có tùy chọn balancing:

```text
BALANCE_DATASETS = True
```

Khi bật balancing, mỗi class được downsample về số lượng của class ít nhất trong train và test.

## 11. Đánh giá mô hình

Mỗi split sinh ra các kết quả:

```text
confusion matrix
classification report
accuracy
precision
recall
f1
```

Quy ước metric:

```text
Task 1, Task 2:
  precision, recall, f1 dùng macro average

Task 3:
  precision, recall, f1 dùng binary average
```

Sau tất cả split, pipeline tổng hợp:

```text
accuracy_mean, accuracy_std
precision_mean, precision_std
recall_mean, recall_std
f1_mean, f1_std
mean confusion matrix
normalized mean confusion matrix
```

Ý nghĩa:

- Accuracy cho biết tỷ lệ dự đoán đúng tổng thể.
- Macro precision/recall/F1 giúp đánh giá công bằng giữa các class, đặc biệt trong bài toán multi-class.
- Confusion matrix cho biết model hay nhầm lẫn giữa những loại nhiễu nào.
- Normalized confusion matrix giúp so sánh theo tỷ lệ thay vì số lượng tuyệt đối.

## 12. Phân tích sau huấn luyện

Sau khi train, pipeline có các bước phân tích.

### Phân tích theo từng dataset

Tạo các bảng và hình:

```text
confusion matrix từng split
confusion matrix trung bình
normalized confusion matrix
feature importance
bảng tổng hợp metric
```

### So sánh global giữa các hệ

Pipeline gom các Step-2 CSV từ nhiều hệ, scale features theo global min-max, sau đó vẽ:

```text
boxplot theo loại nhiễu
line plot theo cường độ nhiễu
boxplot clean vs noisy
```

Mục tiêu là so sánh pattern của complexity metrics giữa ECG, Lorenz, Rössler, Hénon và AR(1).

### XAI

Bước XAI dùng các model CatBoost đã lưu và dùng lại đúng test rows đã được ghi trong split metadata.

Phân tích gồm:

```text
CatBoost feature importance
SHAP importance
permutation importance theo macro F1
```

Mục tiêu là trả lời:

- Feature nào quan trọng nhất để phân biệt nhiễu?
- Feature nào ổn định qua nhiều split?
- Kết quả quan trọng có khác nhau giữa các task và các hệ tín hiệu không?

## 13. Đầu ra chính của pipeline

Về mặt nghiên cứu, các artifact quan trọng gồm:

```text
Step 1:
  Tín hiệu clean/noisy và metadata index

Step 2:
  Bảng complexity metrics theo rolling window
  CSV cho Task 1, Task 2, Task 3

Step 3:
  Model CatBoost từng split
  Confusion matrix từng split
  Classification report từng split
  Metric aggregate

Step 4:
  Hình confusion matrix
  Bảng tổng hợp kết quả theo dataset
  Feature importance plots

Step 5:
  Global comparison plots giữa các hệ

Step 6:
  SHAP importance
  Permutation importance
  XAI summary plots
```

## 14. Cách diễn giải kết quả

Nên đọc kết quả theo thứ tự:

1. Task 3 trước: complexity metrics có phát hiện được clean vs noisy không?
2. Task 1 tiếp theo: nếu biết có nhiễu, model có phân biệt được loại nhiễu không?
3. Task 2 sau cùng: model có phân biệt được cả loại và mức độ nhiễu không?
4. Confusion matrix: model nhầm lẫn giữa những class nào?
5. Feature importance/XAI: những complexity metrics nào đóng góp nhiều nhất?
6. Global comparison: pattern này có lặp lại trên nhiều hệ hay chỉ xảy ra ở một hệ?

## 15. Tóm tắt ngắn gọn

Dự án tạo tín hiệu sạch từ các hệ dynamical/ECG/AR(1), chuẩn hóa z-score, thêm nhiễu Gaussian, pink và low-frequency với nhiều cường độ. Mỗi tín hiệu sau đó được cắt thành rolling windows. Mỗi window được biểu diễn bằng 18 complexity metrics. CatBoostClassifier được dùng để giải quyết 3 bài toán: phân loại loại nhiễu, phân loại loại nhiễu kèm cường độ, và phát hiện có nhiễu hay không. Đánh giá được thực hiện bằng repeated group-aware train/test splits theo `signal_id` để tránh leakage giữa các window của cùng một run. Kết quả được tổng hợp bằng accuracy, precision, recall, F1, confusion matrix, feature importance và các phân tích XAI.
